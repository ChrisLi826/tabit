## v1.9.1 · Aiyu Jelly

The pick lists behind `+ Serial`, `+ tmux` and `+ AI` show things that
live outside tabit, and none of them said which of your own tabs was
already on one. Now they do — and they are right about it.

### Added
- **A session a tab already holds is named.** Each entry in the three
  pick lists carries that tab's group and name, `● QCA2ECW536 · ttyUSB3`.
  A session attached from a terminal outside tabit keeps the plain
  `● open` marker. Two tabs sharing one session both count:
  `● Router · ttyUSB0 +1` — `screen -x` shares on purpose.
- **The serial device dropdown warns about a line in use.** A note under
  it names the tab that already has the selected device. A serial line
  takes one reader at a time, and that is worth knowing before the
  second tab is opened on it.

### Fixed
- **The serial tag names the session the tab is really on.** It used to
  derive `ap-<device>` from the command line. screen.sh attaches to
  whatever session already holds the device, under that session's own
  name, so the derived name did not just miss that session — it labelled
  an unrelated one that happened to carry it. The name is now read from
  the tab's own child process, which is the screen client itself.
- **screen and tmux no longer borrow each other's names.** They are two
  namespaces; a tmux session called `ap-ttyUSB3` is not the screen one.
- **Renaming a tmux session moves our tabs with it**, so they stop
  naming a session that is gone, or one created later under the name.
- **The device note ignores ssh and telnet tabs**, whose target field
  takes free text, and matches through symlinks, so a line opened as
  `/dev/serial/by-id/...` answers for `/dev/ttyUSB0`.
- **Killing a session from the serial dialog clears the device note.**
- **The plain marker's tooltip** said a tab of ours was attached. It is
  shown precisely when none is.
- **The lists cost one pass, not one per entry.** Naming a tab used to
  walk every tab for every row shown, re-parsing each AI tab's tmux
  wrapper each time: 122ms at 30 tabs and 1.3s at 100, now 7.5 and 25.
- **The tab name outranks the path beside it.** The tag clipped itself
  at 26 characters while the path asked for all the room it could get,
  and a narrow dialog starved the tag down to a stub. The tag now runs
  to 38 characters with a floor of 20; the path yields first and keeps
  its full text in a tooltip.
