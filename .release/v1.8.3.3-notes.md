## v1.8.3.3 · Tube Rice Pudding

A third hotfix on v1.8.3, keeping its codename. v1.8.3.1 and v1.8.3.2 both
said a wrapped path was clickable. Inside tmux it was not, and neither was
a row the path filled to the edge.

### Fixed
- **A wrapped path is clickable inside tmux.** VTE numbers rows three
  different ways and this code used the wrong one. `get_text_range` counts
  from the start of the buffer, the shell's own history included, while the
  scrollbar reads 0 for as long as the alternate screen is up -- which is
  the whole time in a tmux tab. Reading the screen from the scrollbar read
  the history from before tmux started instead. The offset measured 25 rows
  on a real tab, so a path near the top of the screen still landed inside
  what was read and one lower down did not: the click opened the file, or
  fell through to tmux and jumped back to the prompt, depending on where on
  the screen the path happened to sit. The screen now reads from the
  cursor, the one row VTE reports in the same numbering, and finding the
  head of a fold asks VTE for the match rather than counting rows.
- **A row the path fills to the last column no longer loses a character.**
  `get_text_range` stops before its end column, so it takes the column
  count, not the last column. A path long enough to fold is exactly what
  fills a row, so the rejoined path was one character short and named no
  file.
