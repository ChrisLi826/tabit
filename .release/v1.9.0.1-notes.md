## v1.9.0.1 · Bubble Tea

A hotfix on v1.9.0, keeping its codename. The notification it added took
two clicks to get anywhere; now it takes one.

### Fixed
- **Clicking the notification opens the tab.** Only its button did
  anything. A notification server invokes the action named `default` when
  the popup body is clicked rather than one of its buttons, and tabit
  registered no such action, so the whole card was dead and the only way
  through was the smaller target inside it. The button stays — a server
  with no default-action support still needs it, and it says what the
  click will do.
- **The notification raises the window instead of asking to.** Clicking it
  put up a second notification, GNOME's own "window is ready", which had to
  be clicked as well. That is focus-stealing prevention doing its job:
  `present_with_time` was being passed `Gdk.CURRENT_TIME`, which is zero
  and reads as "no timestamp at all", and a raise with no timestamp is
  what a window manager refuses from an app the user has not just
  interacted with. The X server's own clock is a timestamp it accepts.
- **Pinning a tab to the right pane clears its popup.** Pinning shows a tab
  without going through the row-selection handler, so the popup stayed up
  over a tab that was now on screen. Fixed where every pane that displays a
  tab passes through, which also covers focusing a pane by keyboard.

cd tabit && git pull && ./install.sh
