## v2.3.5 · Sesame Oil Chicken + Iron Egg

When memory runs low, the system no longer takes tabit and every AI tab
down at once.

### New
- **Each AI tab in its own systemd scope.** When memory runs low,
  systemd-oomd kills a whole scope. Before, every agent ran under one tmux
  server inside tabit's own scope, so one kill took tabit and all AI tabs
  together. Now each agent started in tmux runs in
  `tabit-<session>.scope`, and a tmux server tabit starts runs in
  `tabit-tmux.scope`: one kill takes one tab.
  - Without `systemd-run` or a user systemd, agents start as before.
  - A session that is still open is only attached again.
- **Idle AI tabs sleep when memory is low** (Settings… → AI, on by default).
  - tabit reads the memory pressure systemd-oomd watches every 5 seconds.
    At 20% or more for two looks in a row, it stops the agent of one AI
    tab, the one used longest ago, then waits 30 seconds. systemd-oomd
    kills at 50%, so this comes first.
  - Only a tab that is idle or done, not on screen, and that resumes the
    conversation it is in. A working tab, one that asks something, or one
    with background work is never put to sleep.
  - A sleeping tab stays in the list, marked 💤. Open it and it goes on
    with the same conversation. It stays asleep across a restart until you
    open it.
  - The phone and Tabit Chat say a tab is asleep instead of sending to it.

### Notes
- Restart tabit (or let the update do it). Agents already running move to
  their own scope only when their tab starts again.
